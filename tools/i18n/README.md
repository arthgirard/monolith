# Translating Monolith

`app/src/main/res/values/strings.xml` is the only file anyone edits by hand. Every
`values-<locale>/strings.xml` is generated by `translate.py`.

The point of the pipeline is that raw machine translation fails this app in three specific
ways, and each one has a countermeasure here:

| Failure | Countermeasure |
| --- | --- |
| Tone flattens into polite product English | `brief.md` ships with every request, and a second pass reviews against it |
| Strings naming an Android Settings toggle get invented wording, so the user cannot find it | `aosp_glossary.py` pins those phrases to the labels AOSP actually shows |
| German and French run long and clip in buttons and the widget | per-string `max_chars`, a validator, and the `en-XA` pseudolocale in debug builds |

## Running it

```bash
python3 -m venv .venv && . .venv/bin/activate   # the Fedora system python is missing deps
pip install -r tools/i18n/requirements.txt
export ANTHROPIC_API_KEY=...          # or: ant auth login

python3 tools/i18n/aosp_glossary.py   # refresh Android Settings labels (rarely needed)
python3 tools/i18n/translate.py --dry-run
python3 tools/i18n/translate.py
```

Useful flags: `--locales de,fr`, `--force` (re-translate everything), `--no-critic` (skip
the review pass), `--limit 10` (cheap trial), `--strict` (exit non-zero on any warning),
`--chunk-size`, `--workers`.

Work is incremental. `state.json` records the SHA of the English source behind each
translated string, so adding one string later re-translates that one string. Commit
`state.json` and `glossary.generated.json` along with the generated locale files.

## Adding a locale

Add an entry to `locales.json` (`res` is the Android qualifier, `aosp` the directory name in
AOSP — note `values-pt-rBR`), add the tag to `manual_overrides` in `glossary.json`, add the
qualifier to `localeFilters` in `app/build.gradle.kts`, then run `aosp_glossary.py` and
`translate.py --locales <tag>`.

## What still needs a human

The pipeline gets the whole app to a usable state; it does not replace a native speaker on
the strings that decide whether onboarding succeeds. Have someone read these in each locale
before shipping it:

- the five `perm_*_title` / `perm_*_desc` pairs and `restricted_settings_body`
- `strictness_*` — the three descriptions people choose between
- `overlay_*` and `waiver_*` — the block screen, where the tone matters most
- `bypass_confirm_body` and `activate_confirm_body`

Two known gaps in the automatic glossary: "Install unknown apps" lives in
PermissionController rather than AOSP Settings, so `update_install_permission_*` is
unpinned; and where AOSP lists two variants for a phrase (Android versions differ) the
first is used. Fix either by hand through `manual_overrides` in `glossary.json`, which is
injected into the prompt as a required rendering.

## Checking a locale before shipping

```bash
./gradlew lintDebug              # MissingTranslation and ExtraTranslation are fatal
./gradlew installDebug           # then switch the device language
```

Debug builds carry two pseudolocales: `en-XA`, every string accented and expanded by ~40%,
and `ar-XB`, the same text laid out right-to-left. Walking the app in `en-XA` finds clipping
without needing a real translation.

## Files

| File | |
| --- | --- |
| `brief.md` | The voice and hard rules. The main thing worth editing when output feels off. |
| `locales.json` | Target locales and their Android/AOSP directory qualifiers. |
| `glossary.json` | Do-not-translate terms, the Settings phrases to pin, manual overrides. |
| `glossary.generated.json` | Localised Settings labels fetched from AOSP. Generated. |
| `strings_res.py` | Reads and writes `strings.xml`, preserving order, sections and escaping. |
| `usage_context.py` | Finds where each string is used, so "Clear" arrives as a button. |
| `aosp_glossary.py` | Fetches the Settings labels. |
| `translate.py` | The pipeline. |
| `state.json` | Source hashes behind each translation. Generated. |
